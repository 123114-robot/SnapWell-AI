# Spike B：浏览器端包装标签 OCR

**状态：** 功能已实现，已通过首次手机端验证。

## 验证目标

验证用户能够拍摄或选择一张澳洲包装食品标签图片，并在手机浏览器中读取其英文
文字；图片不会被 SnapWell 上传到服务器。

## 实现说明

- 使用 Tesseract.js 7 和英文（`eng`）OCR worker。
- worker、LSTM core 浏览器兼容版本和英文语言数据均自托管在
  `web/public/tesseract/`，不会从第三方 OCR CDN 下载。仓库体积与首次加载下载量
  是两个不同的数字，见下方"资源体积"一节。
- 第一次执行 OCR 时创建 worker；同一浏览器会话中的后续图片复用该 worker。
- OCR 前对用户手动框选的文字区域进行缩放（最长边最多 1600 px）。系统分别识别保留
  颜色差异的增强版本和二值化版本，并返回置信度较高的结果。
- 用户可框选任意包装文字区域。每次识别结果会追加到同一个可编辑文字字段；页面同时显示
  OCR 进度、置信度和总耗时。这样可分别读取品牌、产品名、配料或过敏原提示，
  而不会把噪声 OCR 强行分类为某个字段。
- 用户所选图片只交由浏览器 API 和 OCR worker 处理，不会由 SnapWell 发往服务端。

首次 OCR 会从 SnapWell 同源网页加载这些 OCR 资源；这不是上传用户图片。当前尚未
加入 Service Worker，因此此 spike 不宣称已实现保证可用的离线体验。

## 资源体积

自托管的 OCR 资源涉及两个不同的数字，不能混用。

**仓库体积 —— 约 22 MB。** 三个 core 兼容版本（plain、SIMD、relaxed SIMD）全部
签入仓库，以覆盖所有目标浏览器。

**首次加载下载量 —— 约 7 MB。** 浏览器只会取自己需要的那一个版本：

| 资源 | 体积 |
|---|---:|
| `worker.min.js` | 0.11 MB |
| 一个 `tesseract-core-*-lstm.wasm.js`（按 SIMD 特性检测选择） | 3.90 MB |
| `eng.traineddata.gz` | 2.95 MB |
| **合计** | **≈ 6.96 MB** |



## 与 proposal 的当前对齐

Spike A 的 COCO 物体检测与 Spike B 的 OCR 目前是在同一页面展示的两个独立技术
验证，尚未融合为分类加 OCR 的完整流程。当前 OCR 不会从噪声中推断品牌或产品名，而是
保留用户框选文字区域的可编辑识别结果。后续 Sprint 将自训设备端 `ingredient_panel`
检测模型，以建议更聚焦的 OCR 输入，同时保留手动调整。

## 手机测试步骤

1. 在 `web/` 目录运行 `npm run dev -- --host`，让手机与电脑连接同一 Wi-Fi，
   再打开终端显示的 Network 地址。
2. 拍摄或选择一张正面、清晰的 Coles/Woolworths 包装食品图片。
3. 框选任意可读的包装文字区域，再点击 **Read selected text locally**；需要时可继续框选
   其他区域。
4. 记录页面显示的总耗时、置信度、识别文字，以及文字是否无需修改即可使用、修改后可用或不可用。
5. 至少测试三种图片：正面清晰、反光/倾斜、文字较小或部分遮挡。
6. 查看浏览器 Network，确认图片本身没有发往远程应用接口，且 OCR 资源来自
   SnapWell 同源网页而不是外部 OCR CDN。同时记录实际取用的是哪个 core 变体，
   以及首次加载的总传输字节数，以便用实测值替换"资源体积"一节中的估算。

## 结果记录

本次更新只使用下列 6 张仓库截图作为证据，文件位于
`src/spike-b-results/`。测试设备为 iPhone 16 Pro。每次均为用户
手动框选文字区域，显示的总耗时包含本地 OCR 工作。

| 证据 | 框选文字 | 总耗时 | 置信度 | 结果 | 观察 |
|---|---|---:|---:|---|---|
| [1-a.jpg](../src/spike-b-results/1-a.jpg) | Sole Mare 正面产品文字 | 85 ms | 93.0% | 可用 | 追加的 OCR 文字正确读出 `SOLE MARE`、`MACKEREL FILLETS` 与 `IN OLIVE OIL`。 |
| [1-b.jpg](../src/spike-b-results/1-b.jpg) | Sole Mare 配料与过敏原面板 | 138 ms | 83.0% | 可用 | 配料列表和 `Contains Fish` 与标签高度一致。 |
| [2-a.jpg](../src/spike-b-results/2-a.jpg) | Kehoe's 艺术字体品牌标志 | 166 ms | 41.0% | 不修改不可用 | 手写／艺术化 logo 无法被可靠识别。 |
| [2-b.jpg](../src/spike-b-results/2-b.jpg) | Kehoe's 配料与过敏原面板 | 152 ms | 64.0% | 部分可用 | 识别到主要配料词，但曲面与反光标签混入邻近文字并产生字符错误。 |
| [3-a.jpg](../src/spike-b-results/3-a.jpg) | Farmers Union Greek Style 产品文字 | 191 ms | 65.0% | 部分可用 | `GREEK` 与 `All Natural Yogurt` 可读；`STYLE` 含一个多余的错误字符。 |
| [3-b.jpg](../src/spike-b-results/3-b.jpg) | Farmers Union 配料与过敏原面板 | 206 ms | 93.0% | 可用 | 框选的配料与 `CONTAINS MILK` 文字与标签高度一致。 |

### 实验发现

- 这 6 次记录的 OCR 总耗时为 **85–206 ms**，平均约 **156 ms**；这是便利样本，不能作为
  正式的延迟基准。
- 对规则、高对比度的印刷文字，聚焦裁剪在 3 个清晰面板例子（`1-a`、`1-b`、`3-b`）均输出
  可用结果。
- 对**艺术字体、反光和曲面标签仍不稳定**。Kehoe's 品牌标志不可用；曲面的 Kehoe's 配料
  区域需要人工修正。
- 置信度只能作为提示，不能证明文字正确。`3-a` 的 65.0% 结果大部分可用；因此所有 OCR
  输出仍必须可编辑，并在进入后续商品或食材匹配前由用户确认。

## 验收标准

- 清晰包装图片能在手机浏览器中输出可读的产品/标签文字。
- 页面展示可编辑的识别文字、置信度和耗时。
- 用户可以在文字用于后续推荐前手动修正。
- SnapWell 应用不上传用户图片。

## 当前限制

- OCR 只负责读取可见文字，尚不会把品牌/商品字符串自动映射为统一食品数据库条目。
- 准确率和速度受光线、对焦、反光、标签角度、文字大小、对比度和字体设计影响；艺术字体、
  反光和曲面标签仍不稳定。
- 当前只验证英文；商品匹配以及 OCR 与 YOLO 结果融合属于 Sprint 2。
