# SnapWell AI

[English README](README.md)

SnapWell 是一个面向澳洲用户、强调隐私保护的移动网页原型。它结合设备端图像
处理、用户确认食材，以及经验证的营养数据，为个性化食谱推荐建立基础。

## 当前原型

### Spike A - 设备端物体检测

- YOLOv8n 通过 ONNX Runtime Web 在浏览器内运行。
- 图像预处理、推理、后处理和检测框绘制均在本地设备完成。
- 当前使用 COCO 预训练模型，因此这一阶段验证的是浏览器端架构和延迟，而不是
  澳洲食品类别的最终准确率。

### Spike B - 本地包装标签 OCR

- 使用 Tesseract.js 在浏览器本地读取包装标签中的英文文字。
- 用户可以通过拍照或相册选择图片；在桌面端也可以把图片拖放到上传区域。OCR 会在
  本地读取用户手动框选的任意包装文字区域。
- 框选区域会按最长边最多 1600 px 缩放；系统会生成保留颜色差异的增强版本和二值化版本，
  分别在本地 OCR，并显示置信度较高的结果。
- 页面将识别文字追加到同一个可编辑字段中。用户可分别框选品牌、产品名、配料或过敏原
  提示，再统一查看和修正文字。
- 页面会显示每次 OCR 的置信度和识别耗时。

SnapWell 应用不会上传用户图片。Tesseract worker、核心文件和英文语言数据均由本
项目的 `/tesseract/` 静态资源提供，不依赖第三方 OCR CDN。这里有两个不同的数字，
不要混淆：仓库中签入的资源约 22 MB，因为包含了三个 core 兼容版本；而浏览器只会
下载其中一个，因此**首次加载实际下载约 7 MB**，之后通常由浏览器缓存。明细见
`docs/spike-b-results.zh.md`。

## 本地运行

前置条件：Node.js 20 或更高版本。

```bash
git clone https://github.com/123114-robot/SnapWell-AI.git
cd SnapWell-AI/web
npm install
npm run dev -- --host
```

在电脑浏览器中打开 Vite 输出的 Local URL。手机测试时，请让手机和电脑连接到
同一个 Wi-Fi，再在手机浏览器中打开终端输出的 Network URL。

## 测试包装标签 OCR

1. 从相机或相册选择一张包装食品图片；桌面端也可以把图片拖放到上传区域。
2. 用手指或鼠标框选任意清晰的包装文字区域，再点击 **Read selected text locally**；需要
   时可继续框选其他区域并追加识别结果。
3. 查看并修正可编辑的识别文字。后续食谱匹配将以用户确认后的结果为输入。

建议拍摄正面、清晰、光线均匀的标签近照。罐身曲面、反光、文字过小或标签中无关
文字过多都会降低识别准确率。双预处理能改善低对比度标签，但也会增加单次 OCR 耗时。

## 验证构建

```bash
npm run build
```

Spike A 的结果记录在 `docs/spike-a-results.en.md`。Spike B 的手机测试步骤和结果
记录在 `docs/spike-b-results.en.md` 与 `docs/spike-b-results.zh.md`。

## 当前范围与限制

- Spike B 只验证本地 OCR 与用户确认流程，尚未把包装商品名称映射到统一的澳洲
  商品或食品数据库条目。
- OCR 读到的包装营养数字不会用于食谱营养计算；proposal 中的营养估算将使用
  AUSNUT 等已验证食品数据。
- OCR 与 YOLO 结果融合属于后续 Sprint；当前以人工引导的文字区域 OCR 生成候选。
- Spike A 和 Spike B 目前同页展示，但仍是两个独立的技术验证，尚未成为融合后的
  产品流程。当前 OCR 不会从噪声中推断品牌、产品名或配料字段，而是保留用户框选区域的
  可编辑识别文字。后续将以更可靠的面板检测和商品映射改进。

   里程碑是在手机拍摄水果或蔬菜后，能得到可编辑食材列表和本地食谱推荐。

   是 Sprint 2 自训检测模型的输入，不是等 UI 完成后才开始的工作。
